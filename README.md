# Poultry EWS — سامانه‌ی هشدار زودهنگام بیماری طیور

این سامانه ویدیوهای ۵ دقیقه‌ای دوربین‌های بالای سالن را تحلیل می‌کند. از آن‌ها چهار سیگنال سلامت گله درمی‌آورد. هر سیگنال را با «حالت عادیِ همین سن و همین ساعت» مقایسه می‌کند. اگر چیزی غیرعادی ببیند، خودش هشدار می‌دهد. یک پنل وب هم دارد که مرغدار و دامپزشک هر وقت بازش کنند، وضعیت لحظه‌ای این چهار سیگنال را می‌بینند.

> این ابزار جایگزین معاینه‌ی دامپزشک نیست. کارش این است که زودتر بگوید «کجا را نگاه کنید».
> آستانه‌ها باید با نظر دامپزشک پروژه روی داده‌های همین مرغداری تنظیم شوند.

## چهار سیگنال

این چهار سیگنال همان‌هایی هستند که در سند پروژه آمده‌اند.

| # | سیگنال | چه چیزی اندازه گرفته می‌شود | معیار اصلی |
|---|---|---|---|
| ۱ | **شاخص فعالیت گله** | Optical Flow روی نقشه‌ی صاف‌شده‌ی کف (واحد: متر بر ثانیه). سهم پیکسل‌های پرنده که در حرکت‌اند | `activity_index` |
| ۲ | **توزیع فضایی** | سهم پرنده‌ها کنار دانخوری و آبخوری، و کنار دیوار و گوشه. پراکندگی گله | `resource_frac`، `periphery_frac` |
| ۳ | **تلفات** | پرنده‌ای که چند ساعت در یک نقطه بی‌حرکت مانده، در حالی که گله فعال بوده. به‌اضافه‌ی تلفات روزانه‌ای که دستی ثبت می‌شود | نامزد تلفات، `daily_mortality_pct` |
| ۴ | **الگوی شبانه‌روزی** | شباهت و شدت ریتم ۲۴ ساعت اخیر در مقایسه با روزهای قبل | `rhythm_corr`، `rhythm_amplitude` |

جزئیات روش، منابع و محدودیت‌های هر سیگنال در [`docs/signals.md`](docs/signals.md) آمده است.

**آنچه این دوربین نمی‌بیند** (طبق بخش آخر سند پروژه): رنگ و قوام مدفوع، رنگ تاج، و تنفس با دهان باز. برای این‌ها دوربین نزدیک یا روش دیگری لازم است. این سامانه برای آن‌ها هشدار نمی‌دهد.

## مسیر داده

```
DVR / دوربین‌ها ─► data/raw/cam1/2025-12-09/05.45.00-05.50.00RO000.h264
                                   │   (هر دوربین پوشه‌ی خودش؛ زمان ضبط از نام فایل)
                                   ▼
  analyzer   ── هر کلیپ، با نرخ ۲ فریم بر ثانیه:
     │          جداسازی پرنده (segmentation) ─► نگاشت به کف سالن (homography، متر)
     │          ├─ Optical Flow ─► فعالیت                       (سیگنال ۱)
     │          ├─ نقشه‌ی اشغال ─► توزیع                         (سیگنال ۲)
     │          └─ پیکسل‌های همیشه‌حاضر و بی‌حرکت ─► لکه‌ی بی‌حرکت    (سیگنال ۳)
     ▼
  pipeline   ── ادغام دوربین‌های یک سالن در هر بازه‌ی ۵ دقیقه‌ای
     │          baseline: میانه و MAD همین ساعت، در روزهای قبل و دوره‌های قبل
     │          ریتم ۲۴ ساعته                                    (سیگنال ۴)
     │          ردیابی نامزدهای تلفات بین کلیپ‌ها
     ▼
  alerts     ── قوانین configs/rules.yaml (z-score / آستانه، تداوم، فاصله‌ی تکرار)
     ▼
  SQLite ──► پنل وب (FastAPI) + webhook برای ارسال پیام
```

## راه‌اندازی

```bash
git clone <this-repo> && cd poultry-ews
python -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"

cp configs/farm.example.yaml configs/farm.yaml
cp configs/cameras/cam1.example.yaml configs/cameras/cam1.yaml
# در farm.yaml: ابعاد سالن، تاریخ جوجه‌ریزی، تعداد جوجه، دوربین‌ها و سالن‌ها
```

### ۱) کالیبراسیون، برای هر دوربین

```bash
# روی یک کامپیوتر با صفحه‌نمایش (نسخه‌ی کامل opencv-python):
pews calibrate --camera cam1 --image frame.png --valid-from 2025-12-01

# بعد از هر تغییر، حتماً پیش‌نمایش را ببینید:
pews preview --camera cam1 --image frame.png --out preview.jpg
```

فایل پیش‌نمایش را باز کنید و این‌ها را چک کنید:
- خطوط سبز (شبکه‌ی ۵۰ سانتی) روی کف می‌نشینند.
- دایره‌های دانخوری و آبخوری سر جای خودشان هستند.
- پرنده‌ها قرمز شده‌اند و بستر قرمز نشده.

هر بار دوربین جابه‌جا شد، یک نسخه‌ی جدید با `--valid-from` بسازید. راهنمای کامل: [`docs/calibration.md`](docs/calibration.md)

### ۲) پردازش ویدیوهای قبلی

اول ویدیوهای دوره‌ی قبل را پردازش کنید تا baseline ساخته شود:

```bash
pews process --camera cam1 data/raw/cam1/
```

### ۳) کار دائمی

```bash
pews watch                    # پوشه‌ی هر دوربین را پایش و کلیپ‌های جدید را پردازش می‌کند
pews serve --port 8000        # پنل: http://<server>:8000/
```

برای گذاشتن رمز روی پنل، `PEWS_USER` و `PEWS_PASSWORD` را تنظیم کنید. پنل را فقط روی شبکه‌ی داخلی مرغداری یا VPN باز کنید.

### دیدن پنل با داده‌ی نمایشی

```bash
python scripts/make_demo.py
pews serve --config demo/configs/farm.yaml
```

داده‌ی این حالت شبیه‌سازی‌شده است، نه واقعی.

```
  segmentation.py          رنگی (مرحله‌ی ۱) | YOLO (مرحله‌ی ۲) | تشخیص‌های خارجی (مرحله‌ی ۳)
  signals/activity.py      سیگنال ۱
  signals/distribution.py  سیگنال ۲
  signals/mortality.py     سیگنال ۳

  analyzer.py              تحلیل یک کلیپ از یک دوربین
  pipeline.py              ادغام، baseline، ردیابی تلفات، پایش پوشه‌ها
  baseline.py              «حالت عادی» بر اساس سن و ساعت
  alerts.py                موتور هشدار و پیام‌های فارسی
  api/app.py, static/      پنل وب
  calibrate.py, preview.py ابزارهای کالیبراسیون
docs/                      روش‌ها، کالیبراسیون، راهنمای برچسب‌زنی، نقشه‌ی راه
tests/                     آزمون‌ها روی ویدیوی مصنوعی (pytest)
data/samples/              هفت فریم نمونه از cam1 (نوامبر و دسامبر ۲۰۲۵)
```

## مراحل توسعه

| مرحله | تشخیص پرنده | وضعیت |
|---|---|---|
| ۱ | جداسازی رنگی، بدون نیاز به آموزش | **پیاده‌سازی شده.** برای فعالیت و توزیع کافی است. برای تلفات در تجمع‌های فشرده ضعیف است |
| ۲ | YOLO-seg آموزش‌دیده روی فریم‌های همین مرغداری | آداپتور آماده است. داده‌ی برچسب‌خورده لازم دارد: [`docs/labeling_guide.md`](docs/labeling_guide.md) |
| ۳ | ردیابی چنددوربینه‌ی MVBroTrack | از طریق `ExternalDetections`؛ توضیح در [`docs/roadmap.md`](docs/roadmap.md) |

**درباره‌ی MVBroTrack:** کد آن پروژه (`decide-ugent/multi-view-broiler-tracking`) با لایسنس AGPL-3.0 منتشر شده. این مخزن هیچ کدی از آن کپی نکرده و فقط از روی فایل با آن ارتباط می‌گیرد. اگر روزی کدش را داخل این سرویس ادغام کنید، شرایط AGPL شامل کل سرویس می‌شود. لایسنس این مخزن را خودتان انتخاب کنید (فعلاً فایل LICENSE ندارد).

## آزمون‌ها

```bash
pytest -q
```

۲۷ آزمون هست. ویدیوی مصنوعی با پرنده‌های متحرک و ثابت می‌سازند و این‌ها را بررسی می‌کنند: فعالیت، توزیع، هشدار تلفات بعد از ۱۵ دقیقه بی‌حرکتی، هشدار افت فعالیت بعد از ۳ بازه‌ی پشت‌سرهم، تکرارناپذیری پردازش مجدد، و API.
